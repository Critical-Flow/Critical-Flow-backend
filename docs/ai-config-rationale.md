# AI 설정값 및 수치 선택 이유

---

## RAG 설정

### similarity-threshold: 0.75

cosine 유사도 기준 0.0(완전 다름) ~ 1.0(완전 동일) 스케일에서 0.75는 **"같은 개념 영역 내의 관련 노트"** 를 잡아내는 경험적 기준값이다.

| 값 | 결과 |
|----|------|
| 0.9 이상 | 거의 같은 내용의 노트만 통과 → 검색 결과가 너무 없음 |
| 0.6 이하 | 무관한 노트까지 통과 → RAG 노이즈 증가 |
| **0.75** | "재귀 함수" 노트가 "스택/콜스택" 노트를 잡아낼 수 있는 수준 |

2차 키워드 필터(`isTopicRelevant`)가 추가로 걸러주므로 다소 느슨하게 설정 가능.

---

### max-results: 4

GPT-4o의 컨텍스트 윈도우(128k 토큰)는 충분하지만, 과거 노트가 많을수록 **시스템 프롬프트가 길어져 현재 노트 집중도가 떨어진다.**

| 값 | 결과 |
|----|------|
| 1~2개 | 연계 맥락이 부족함 |
| **4개** | 관련 과거 노트를 충분히 커버하면서 프롬프트 길이를 통제 가능한 상한 |

실제 검색 시 `topK = max-results + 2 = 6`으로 여유 있게 가져온 뒤 2차 필터 후 4개로 제한.

---

### focus-lookback-minutes: 15

집중 이탈 이벤트(GAZE_OUT, DROWSY, ABSENT)는 **현재 학습 상태**를 반영해야 의미가 있다. 너무 오래된 이벤트를 참조하면 이미 회복된 상태를 문제로 오해할 수 있다.

| 값 | 결과 |
|----|------|
| 5분 | 너무 짧아 일시적 이탈도 못 잡음 |
| 30분 이상 | 오래전 이탈을 현재 상태로 오해할 위험 |
| **15분** | 현재 집중 상태를 판단하기에 적절한 슬라이딩 윈도우 |

## AI 모델 설정

### model: gpt-4o

소크라테스식 꼬리 질문은 단순 정보 전달이 아니라 **학습자의 사고 흐름을 파악하고 적절한 다음 질문을 설계**하는 추론 작업이다.

| 모델 | 평가 |
|------|------|
| gpt-4o-mini | 비용 절감되지만 복잡한 교육적 추론에서 질이 낮아짐 |
| **gpt-4o** | 긴 대화 히스토리 + RAG 컨텍스트 + 집중 이벤트를 종합해 적절한 질문 생성 가능 |

---

### temperature: 0.3

AI 튜터는 **일관성**이 중요하다. 같은 학습 상황에서 매번 다른 방향의 질문이 나오면 학습자가 혼란스럽다.

| 값 | 결과 |
|----|------|
| 0.0 | 너무 딱딱하고 반복적인 패턴 |
| 0.7 이상 | 창의적이지만 교육적 일관성 저하, 엉뚱한 방향으로 빠질 위험 |
| **0.3** | 약간의 변주를 허용하면서도 소크라테스식 질문 흐름의 일관성을 유지 |

---

### embedding: text-embedding-3-small

노트 간 토픽 유사도 비교가 목적이므로 **의미론적 유사도**에 집중하면 된다.

| 모델 | 평가 |
|------|------|
| text-embedding-3-large | 성능이 더 높지만 비용 5배, 속도 느림 |
| **text-embedding-3-small** | 토픽 수준의 유사도 검색에 충분한 성능(1536차원), 비용·속도 대비 효율적 |

## ChromaDB HNSW 설정

### ef_construction: 100 / ef_search: 100

인덱스 구축 정확도와 검색 정확도 파라미터. 기본값(100)을 그대로 사용.

- 수십~수백 건의 학습 노트 규모에서는 이 값을 올려도 체감 차이 없음
- 수십만 건 이상 규모가 되면 조정 검토 필요

### max_neighbors: 16

HNSW 그래프에서 각 노드가 연결하는 이웃 수. 기본값(16) 사용.

- 값이 클수록 검색 정확도 상승, 메모리·구축 시간 증가
- 학습 노트 규모에서는 기본값으로 충분
