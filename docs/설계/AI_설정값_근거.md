# AI 설정값 및 선택 이유

---

## RAG 설정

### similarity-threshold: 0.55

#60 측정 실험 결과 0.75에서 0.55로 변경. Dense 단독 검색 시 10개 쿼리 중 7개가 0건 반환되는 문제를 확인했다. 한국어 CS 노트 간 코사인 거리가 0.41~0.71 범위에 분포하며, 0.75 기준에서 대부분의 노트 쌍이 통과하지 못한다.

| 값 | 결과 |
|----|------|
| 0.75 | 한국어 CS 노트 간 유사도 대부분 미달 → Dense 검색 7/10 빈 결과 |
| **0.55** | 퀵정렬↔버블정렬(유사도 0.62), BFS↔DFS(유사도 0.74) 통과 — Recall@4 목표 달성 |
| 0.4 이하 | 무관한 노트까지 통과 → RAG 노이즈 증가 |

2차 키워드 필터(`isTopicRelevant`)가 추가로 걸러주므로 다소 넓게 설정 가능.

---

### max-results: 4

GPT-4o의 컨텍스트 윈도우(128k 토큰)는 충분하지만, 과거 노트가 많아질수록 **시스템 프롬프트가 길어져 현재 노트 집중도가 떨어진다.**

| 값 | 결과 |
|----|------|
| 1~2개 | 연계 맥락이 부족함 |
| **4개** | 관련 과거 노트를 충분히 커버하면서 프롬프트 길이를 통제 가능한 상태 |

실제 검색 시 `topK = max-results + 2 = 6`으로 사전 여유 있게 가져온 다음 2차 필터 후 4개로 제한.

---

### bm25-max-results: 10

Sparse 검색(키워드 기반)에서 후보를 수집하는 수. `0`으로 설정하면 Sparse 검색을 건너뛰어 Dense-only 모드로 동작한다 (#62 측정 실험에서 비교용으로 사용).

| 값 | 결과 |
|----|------|
| **10** | Dense가 놓친 정확한 식별자·키워드 포함 노트를 충분히 후보로 수집 |
| 0 | Dense-only 모드 (측정용 스위치) |

---

### focus-lookback-minutes: 15

집중 이탈 이벤트(GAZE_OUT, DROWSY, ABSENT)는 **현재 학습 상태**를 반영해야 의미가 있다. 너무 오래된 이벤트를 참조하면 이미 회복된 상태를 문제로 오해할 수 있다.

| 값 | 결과 |
|----|------|
| 5분 | 너무 짧아 일시적 이탈도 못 잡음 |
| 30분 이상 | 오래된 이탈을 현재 상태로 오해할 위험 |
| **15분** | 현재 집중 상태를 판단하기에 적절한 슬라이딩 윈도우 |

## AI 모델 설정

### model: gpt-4o

소크라테스식 꼬리 질문은 단순 정보 전달이 아니라 **학습자의 사고 흐름을 파악하고 적절한 다음 질문을 설계**하는 추론 작업이다.

| 모델 | 평가 |
|------|------|
| gpt-4o-mini | 비용 절감되지만 복잡한 교육적 추론에서 질이 낮아짐 |
| **gpt-4o** | 긴 대화 히스토리 + RAG 컨텍스트 + 집중 이벤트를 종합해 적절한 질문 생성 가능 |

질문 유형 분류(`QuestionTypeRouter`)는 동일한 gpt-4o를 사용한다. 코드 블록이 있는 노트는 LLM 호출 없이 규칙 기반으로 TYPE_E를 즉시 반환해 비용을 절감한다.

---

### temperature: 0.3

AI 튜터는 **일관성**이 중요하다. 같은 학습 상황에서 매번 다른 방향의 질문이 나오면 학습자가 혼란스럽다.

| 값 | 결과 |
|----|------|
| 0.0 | 너무 딱딱하고 반복적인 패턴 |
| 0.7 이상 | 창의적이지만 교육적 일관성 저하, 엉뚱한 방향으로 빠질 위험 |
| **0.3** | 약간의 변주를 허용하면서도 소크라테스식 질문 흐름의 일관성을 유지 |

---

### embedding: text-embedding-3-small

노트 간 토픽 유사도 비교가 목적이므로 **의미론적 유사도**에 집중하면 된다.

| 모델 | 평가 |
|------|------|
| text-embedding-3-large | 성능이 더 높지만 비용 5배, 속도 느림 |
| **text-embedding-3-small** | 토픽 수준의 유사도 검색에 충분한 성능(1536차원), 비용·속도 대비 효율적 |

#57 측정에서 코드+자연어 혼합 문서를 원본 그대로 처리할 때 Recall@4 100% 달성 확인. 전처리(코드 블록 식별자 목록 변환) 적용 시 Recall@4가 40%로 하락하여 전처리를 제거하고 원본 그대로 임베딩하는 방식으로 전환했다.

## ChromaDB HNSW 설정

### ef_construction: 100 / ef_search: 100

인덱스 구축 시 탐색 범위와 검색 시 탐색 범위 파라미터. 기본값(100) 그대로 사용.

- 수백~수천 건의 학습 노트 규모에서는 이 값을 올려도 체감 차이 없음
- 수십만 건 이상 규모가 되면 조정 검토 필요

### max_neighbors: 16

HNSW 그래프에서 각 노드가 연결하는 이웃 수. 기본값(16) 사용.

- 값이 클수록 검색 정확도 상승, 메모리·구축 시간 증가
- 학습 노트 규모에서는 기본값으로 충분
