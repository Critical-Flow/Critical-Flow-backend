## 측정 전략

Java 단에서 각 임계값(0.55 / 0.60 / 0.70 / 0.75) 통과 여부를 비교한다.

- 측정 환경: 노트 20개 ChromaDB 임베딩 (CS 개념·알고리즘·프레임워크 혼합)
- 임베딩 모델: `text-embedding-3-small`

## 문제 원인 분석

`similarity-threshold: 0.75`는 `text-embedding-3-small` 모델 + 한국어 CS 노트 환경에서 **달성 불가능한 값**이었다.

- 전체 최고 score: **0.7139** (DFS 노트 → 시간복잡도)
- Dense 검색 실질 반환 건수: **항상 0건**
- 결과: RAG 컨텍스트가 Sparse(키워드) 검색에만 전적으로 의존

## 수정 내용

| 항목 | 수정 전 | 수정 후 |
|------|---------|---------|
| `rag.similarity-threshold` | 0.75 | **0.55** |

**0.55 선택 근거:**
- score 분포 중앙값이 0.58~0.62 구간
- 0.55 기준 평균 7.3건 반환 → topK=6 제한으로 상위 6건 활용
- 0.60 대비 2건 더 확보, Dense 기여도 향상
- 0.55~0.60 구간 false positive는 `isTopicRelevant()` 2차 필터가 처리

## 결론

**`similarity-threshold: 0.75` → `0.55` 변경 완료**

- 기존 0.75는 이 모델+데이터 환경에서 Dense 검색을 사실상 비활성화시킨 값
- 0.55 적용 후 Dense 검색이 평균 5.8건 반환 → Sparse와 RRF 병합으로 하이브리드 검색 정상화
- BFS↔DFS 유사도(0.26)처럼 의미상 밀접하나 임베딩 유사도가 낮은 경우 → Sparse 검색이 키워드로 보완
- 향후 노트 수 증가 시 score 분포 재측정 및 임계값 재조정 권장
