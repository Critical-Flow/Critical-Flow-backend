## 문제 원인 분석

### Dense가 낮은 이유
- similarity-threshold=0.55 → 코사인 거리로 ≤ 0.45인 노트만 반환
- `text-embedding-3-small` 모델에서 CS 노트 간 대부분의 거리가 0.41~0.71 범위
- 결과: 퀵정렬↔정렬 알고리즘 비교(거리 0.41), 이진탐색↔BFS(거리 ~0.39) 같은 매우 유사한 쌍만 Dense 통과

### 하이브리드 향상 메커니즘
- **Sparse 검색**이 Dense가 놓친 관련 노트를 키워드 매칭으로 보완
- 예: noteId=4(이진 탐색) → Dense 0건이지만 Sparse가 "이진", "탐색", "O(log" 등 키워드로 10건 후보 확보 → 퀵정렬, 시간복잡도 발견

### 한계 — noteId=10(힙) 0건 문제
- Sparse가 10건 후보를 찾았으나 `isTopicRelevant()` 2차 필터에서 전부 제거됨
- 원인: 힙 노트의 핵심 키워드("최대힙", "최소힙", "O(log", "heapify")가 다른 노트 텍스트에 등장하지 않아 오버랩 10% 기준 미달
- 이 경우 2차 필터가 과도하게 작동하여 Recall을 낮춤

## 해석

1. **카테고리 A(기술 식별자)에서 Sparse 효과 극대화**: Recall 0.12 → 0.47, 3.9배 향상. Dense가 의미 기반 유사도를 잡지 못한 "이진 탐색↔시간복잡도", "퀵정렬↔이진 탐색" 연결을 Sparse가 "O(log", "정렬", "알고리즘" 키워드로 보완.

2. **카테고리 B(한국어 CS 용어)에서 일부 효과**: Recall 0.23 → 0.38. 트리 순회(0.00→0.75)에서 두드러지지만 스택/큐(각 0.25 유지)에서는 개선 없음. `isTopicRelevant()` 2차 필터가 스택↔재귀, 큐↔힙 같은 개념적 연결을 키워드 기반으로 확인하지 못해 Sparse 후보가 제거됨.

3. **Dense-only의 근본 한계**: threshold=0.55 환경에서 노트 10개 쿼리 중 7개가 Dense 0건. 의미 기반 검색만으로는 CS 개념 간 연결을 충분히 찾지 못함.

## 결론

**하이브리드 도입 효과 확인 ✅**

- 카테고리 A: +0.35 (10%p 기준 3.5배 초과)
- 카테고리 B: +0.15 (10%p 기준 1.5배 초과)
- 두 카테고리 모두 의미 있는 Recall@4 향상 → 하이브리드(Dense + Sparse + RRF) 구조 유지 권장

**향후 개선 고려사항**:
- `isTopicRelevant()` 2차 필터: 힙처럼 전문 용어가 많은 노트에서 과도하게 작동 → 임계값 추가 조정 또는 필터 조건 재검토 필요
- `bm25-max-results` 현행 10 유지: Sparse 후보 확보에 충분함
