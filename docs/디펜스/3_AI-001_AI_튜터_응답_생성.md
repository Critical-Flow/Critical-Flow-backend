# AI-001 AI 튜터 응답 생성 — 디펜스

> 관련 코드: `AiTutorService`, `FocusEventFormatter`, `RagRetrievalService`  
> 관련 요구사항: REQ-AIV-007, 008, 009, 010

---

## 1. 기능 개요

학습자가 AI 튜터 대화 세션에서 메시지를 전송하거나 대화가 최초 시작될 때, 학습자가 현재 학습 중인 노트 내용을 깊이 이해할 수 있도록 사고를 유도하는 단일 질문 또는 세션 요약을 반환한다.

**AI 튜터 절대 규칙 (Iron Rules):**
- 완성된 코드를 응답에 포함하지 아니한다
- 직접적 정답을 응답에 포함하지 아니한다
- 하나의 응답에 정확히 1개의 질문만 포함한다 (요약 응답 모드 제외)
- 최대 연속 질문 횟수 초과 시 요약 응답 모드로 전환한다

---

## 2. 응답 생성 흐름

```
POST /api/v1/conversations/{id}/messages
    │
    ▼
AiTutorService.respond(conversationId, userMessage)
    │
    ├── [무의미 발화 감지]
    │       length < 5 또는 FILLER_WORDS 포함?
    │       YES → 직전 AI 질문 재제시 (LLM 호출 없음)
    │
    ├── RagRetrievalService.retrieve()
    │       → Dense + Sparse + RRF → RagContext
    │
    ├── FocusEventFormatter.format()
    │       → 최근 15분 집중 이탈 이벤트 조회 → {focus_events}
    │
    └── ChatClient 호출 (QuestionTypeAdvisor 체인)
            → QuestionTypeAdvisor → TYPE 주입
            → gpt-4o 호출 → TutorResponse 반환
```

## 4. Q&A — 행동 규약 구현

### Q. REQ-AIV-010 — 요약 응답 모드 전환이 어떻게 구현되어 있는가?

`MAX_QUESTIONS = 5` 상수로 결정론적으로 제어된다.

```java
// AiTutorService.java
private static final int MAX_QUESTIONS = 5;

// respond() 반환 시
return TutorResponse.builder()
        .summaryMode(questionCount + 1 >= MAX_QUESTIONS)
        .questionCount((int) questionCount + 1)
        .build();
```

LLM 출력과 무관하게 카운트가 기준값에 도달하면 `summaryMode=true`가 된다. REQ-AIV-010은 결정론적 동작이므로 위반율 임계 기반이 아닌 일반 통합 테스트로 검증 가능하다.

### Q. 무의미 발화 판정 기준은 무엇인가?

두 기준을 조합해 판정한다.

```java
private boolean isMeaninglessInput(String message) {
    if (message == null) return true;
    String trimmed = message.trim();
    if (trimmed.length() < 5) return true;               // 길이 기준
    return FILLER_WORDS.contains(trimmed.toLowerCase()); // 어휘 목록 기준
}

private static final Set<String> FILLER_WORDS = Set.of(
    "아", "어", "음", "몰라", "모르겠어", "모름", "..", "...", "idk", "?"
);
```

무의미 발화 감지 시 LLM 호출 없이 직전 AI 질문을 재제시한다(`reanchor()`).

```java
// AiTutorService.java
String lastAiQuestion = history.stream()
        .filter(m -> m.getRole() == MessageRole.AI)
        .reduce((first, second) -> second)   // 마지막 AI 메시지 추출
        .map(AiMessage::getContent)
        .orElse("어떤 부분이 막히는지 조금 더 구체적으로 말해줄 수 있어?");  // 기본 문구

String reanchorContent = "조금 막히는 것 같네. 다시 한 번 — " + lastAiQuestion;
```

직전 AI 질문이 없으면(대화 첫 턴에서 무의미 발화) 기본 문구를 사용한다. LLM 호출이 없으므로 토큰 낭비 없이 빠르게 응답한다.

### Q. REQ-AIV-008 — 정답 미포함이 어떻게 보장되는가?

코드 수준의 강제가 아닌 **시스템 프롬프트(LAW)와 질문 유형 설계**로 보장한다.

- 시스템 프롬프트에 "절대 완성된 정답 코드를 뱉거나 직접적인 답을 주지 마세요" 규칙이 명시되어 있다.
- 각 TYPE 설명에도 "수정된 코드나 정답 구현을 절대 제공하지 않는다 (LAW 1)" 조건이 포함되어 있다.

**검증 방식:** 정답을 요구하는 명시적 발화 전송 후 응답 내 정답 포함 여부를 수동 검수한다. LLM 출력이 확률적이므로 위반율 임계 기반 모니터링으로 검증한다.

**현재 임계값:** `[TBD]` — 미확정 상태.

### Q. REQ-AIV-009 — 단일 질문 포함이 어떻게 보장되는가?

시스템 프롬프트에 "한 응답에 정확히 하나의 질문만을 포함하여야 한다"가 명시되어 있다.

### Q. REQ-AIV-007 — LLM 빈 응답·오류 시 재시도 안내가 구현되어 있는가?

**미구현 상태다.** 현재 `chatClient.prompt()...call()` 호출에 try-catch가 없어, LLM 오류 발생 시 예외가 `GlobalExceptionHandler`로 전달되어 500이 반환된다.

| DRD 명세 | 현재 동작 |
|---|---|
| LLM 타임아웃·오류 → 502 + 재시도 안내 | 500 반환 |
| 빈 응답 수신 → 200 + 재질문 유도 | 500 반환 |

개선 방향: `chatClient.prompt()...call()` 호출을 try-catch로 감싸고, 예외 유형에 따라 적절한 HTTP 상태 코드와 안내 메시지를 반환해야 한다.

## 5. Q&A — 집중도 데이터 활용

### Q. FocusEventFormatter는 어떤 역할을 하는가?

IoT 디바이스(카메라 기반 집중도 추적)가 기록한 집중 이탈 이벤트를 DB에서 조회하고, System Prompt의 `{focus_events}` 변수에 주입할 텍스트로 포맷팅한다.

**조회 조건:** 현재 세션(`sessionId`)의 최근 15분(`focus-lookback-minutes`) 이내 이벤트

**출력 예시 (이벤트 있을 때):**
```
[GAZE_OUT | 8s | alerted=false]
[DROWSY | 23s | alerted=true]
[ABSENT | 45s | alerted=true]
```

| 이벤트 타입 | 의미 |
|---|---|
| `GAZE_OUT` | 시선이 화면 밖으로 이탈 |
| `DROWSY` | 졸음 감지 |
| `ABSENT` | 자리 이탈 |

---

### Q. 집중 이탈 이벤트를 매 응답마다 반영하는가?

그렇지 않다. 시스템 프롬프트 LAW 5(집중도 이벤트 절제된 활용)에 따라 유의미한 패턴(긴 이탈, 반복 이탈 등)이 있을 때만 반영한다. 단순 시선 이탈(예: 듀얼 모니터 사용 가능성)을 극단적인 "딴짓/무기력"으로 과대 해석하지 않도록 지시되어 있다.

## 6. Q&A — RAG 컨텍스트 포맷

### Q. RagContext.format()의 레이블 텍스트를 명시한 이유는?

초기 구현에서 레이블 없이 청크 내용만 주입했을 때, LLM이 과거 노트를 "현재 노트의 일부"로 오해해 해당 내용을 기반으로 직접 답을 제공하는 현상이 발생했다.

```
[참고용 과거 노트 — 현재 노트 학습 보조 목적으로만 활용]

--- [Note: "HashMap 정리" | session_id: 42 | similarity: 0.83] ---
...
```

이 레이블이 과거 노트의 역할을 LLM에게 명시적으로 알려 LAW 4(RAG 노이즈 거부)와 함께 동작한다.

결과가 없을 때는 `(No relevant past notes found.)`를 반환하며, `isEmpty()` 메서드로 결과 유무를 확인할 수 있다. `QuestionTypeRouter`에서 TYPE_C 선택 가능 여부를 판단할 때도 이 메서드를 사용한다.
