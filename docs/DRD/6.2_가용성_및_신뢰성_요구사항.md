# 6.2 가용성 및 신뢰성 요구사항 (Availability & Reliability)

본 절은 시스템이 만족하여야 할 가용성 및 장애 복구 목표를 정의한다. 단일 인스턴스 운영을 전제로 하며, 이중화·로드밸런싱은 현재 범위에 포함되지 아니한다.

---

## 6.2.1 가용성 목표 (Uptime)

| 구분 | 목표 | 비고 |
|---|---|---|
| 시스템 가용률 | 95% 이상 | 예정된 점검 시간 제외 |
| 측정 단위 | 월간 기준 | — |

> 가용률 95%는 월간 약 36시간의 다운타임을 허용한다. AI 기능은 외부 OpenAI API 의존성이 있으므로, OpenAI 서비스 장애 시간은 시스템 가용률 측정에서 제외한다.

---

## 6.2.2 복구 목표 (RTO / RPO)

| 지표 | 목표 | 설명 |
|---|---|---|
| RTO (복구 시간 목표) | 2시간 이내 | 장애 발생 후 서비스 정상화까지 최대 허용 시간 |
| RPO (복구 시점 목표) | 24시간 이내 | 장애 발생 시 허용 가능한 최대 데이터 손실 범위 |

> **RTO 근거:** 단일 인스턴스 재시작 또는 재배포로 복구 가능한 수준. 자동 복구 메커니즘은 현재 구현되어 있지 않으며, 수동 개입을 전제로 한다.

> **RPO 근거:** 학습 노트·대화 기록은 MySQL에 저장되며, 임베딩 벡터는 ChromaDB에 저장된다. 주기적 백업 정책은 [TBD]. 임베딩 손실 시 `POST /api/notes/reembed` 전체 재임베딩 엔드포인트로 복구 가능하다.

## 6.2.3 부분 장애 시 동작

### 외부 LLM 서비스 장애 (OpenAI API)

| 장애 유형 | 시스템 동작 | HTTP 상태 코드 |
|---|---|---|
| LLM 응답 타임아웃 | 학습자에게 재시도 안내 메시지 반환 | 502 Bad Gateway |
| LLM 빈 응답 수신 | 학습자에게 재질문 유도 메시지 반환 | 200 OK |
| LLM 그 외 오류 | 학습자에게 재시도 안내 메시지 반환 | 502 Bad Gateway |

> LLM 장애 시 AI 튜터 응답 생성(AI-001)은 중단되나, 노트 CRUD·대화 조회 등 LLM 비의존 기능은 정상 동작하여야 한다.

> **현재 구현 상태:** `GlobalExceptionHandler`가 미처리 예외를 500으로 처리한다. LLM 특정 오류를 502로 구분하는 핸들러는 미구현 상태이다.

---

### 관련 노트 검색 장애 (ChromaDB)

| 장애 유형 | 시스템 동작 |
|---|---|
| ChromaDB 검색 오류 | 빈 관련 노트 컨텍스트를 반환하고, AI-001 호출은 정상 수행 |
| ChromaDB 임베딩 저장 오류 | 노트 저장은 성공으로 처리하고, 임베딩 실패를 로깅 |

> RAG 검색은 AI 튜터의 보조 컨텍스트이므로, 검색 장애가 전체 응답 생성을 중단시켜서는 아니된다.

> **현재 구현 상태:** `RagRetrievalService`와 `NoteService`에 예외 처리가 없어, ChromaDB 장애 시 예외가 상위로 전파되어 500 오류가 반환된다. DRD 명세(빈 컨텍스트 반환 후 계속 수행)와 다르게 동작하며, try-catch 및 폴백 처리가 필요하다.
