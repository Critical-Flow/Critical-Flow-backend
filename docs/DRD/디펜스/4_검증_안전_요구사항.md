## 5.4.2.1 입력 검증

### REQ-AIV-001 — 노트 본문 길이 초과 시 요청 거부 ⬜ 미구현

**요구사항:** 노트 본문 입력의 길이가 허용 범위를 초과하는 경우 요청을 거부하여야 한다.

**현재 상태:** 코드에 길이 제한 검증 로직이 없다. 노트가 매우 길면 OpenAI API 토큰 한도 초과로 오류가 발생할 수 있으며, 이 경우 500이 반환된다.

**개선 방향:**
- `NoteController` 또는 `NoteService`에서 `content.length()`를 검사해 허용 범위 초과 시 400 Bad Request 반환
- 허용 범위 수치는 `[TBD]` — OpenAI API 토큰 한도와 평균 노트 길이를 고려해 결정 필요

## 5.4.2.2 컨텍스트 격리 (사용자 데이터 격리)

### REQ-AIV-002 — 검색 결과에 요청 학습자 본인 노트만 포함 ✅

**요구사항:** 관련 노트 검색 결과에는 요청 학습자 본인의 노트만 포함되어야 한다.

**구현:** Dense·Sparse 두 검색 모두 ChromaDB `filterExpression`에 `user_id == '{userId}'` 조건 적용.

```java
// RagRetrievalService.denseSearch()
.filterExpression("user_id == '" + userId + "' && note_id != '" + excludeNoteId + "'")
```

ChromaDB 단계에서 필터링되므로 다른 사용자의 노트는 벡터 유사도 계산 자체가 수행되지 않는다.

**검증 방법:** 학습자 A 자격증명으로 학습자 B 노트와 유사한 쿼리 전송 후 응답 내 노트 소유자 확인 → 타 학습자 노트 미반환 확인.

---

### REQ-AIV-003 — 현재 노트 자신이 검색 결과에 포함되지 않음 ✅

**요구사항:** 관련 노트 검색 결과에는 현재 조회 중인 노트 자신이 포함되어서는 아니된다.

**구현:** `filterExpression`에 `note_id != '{excludeNoteId}'` 조건 적용.

**필요한 이유:** RAG 검색 쿼리가 현재 노트의 원문 전체이므로 제외하지 않으면 벡터 유사도가 1.0에 가까워 자기 자신이 항상 1위로 반환된다. 실제로 필요한 과거 관련 노트들이 밀려나는 문제가 생긴다.

**검증 방법:** 현재 노트 내용과 동일한 쿼리로 검색 요청 후 결과 내 해당 노트 식별자 미존재 검증.

---

### REQ-AIV-004 — 관련도 임계값 미만 항목 제외 ✅

**요구사항:** 관련도가 임계값 미만인 항목은 결과에서 제외되어야 한다.

**구현:** 세 단계 필터로 처리된다.

| 단계 | 필터 | 기준 |
|---|---|---|
| 1차 (Dense) | ChromaDB `similarityThreshold=0.55` | 유사도 0.55 미만 문서 제거 |
| 1차 (Sparse) | 키워드 `anyMatch` | 추출된 키워드 중 하나도 포함되지 않은 문서 제거 |
| 2차 (`isTopicRelevant`) | 키워드 오버랩 ≥ 10% | RRF 병합 후 키워드 일치율 10% 미만 제거 |

**임계값 0.55 선택 근거:** #60 측정에서 0.75 기준 Dense 평균 반환 0건 확인 → 0.55로 변경 후 평균 5.8건 반환. 노트 20개 기준 측정값이므로 노트 수 증가 시 재검토 필요.

## 5.4.2.3 프롬프트 인젝션 / 시스템 지시 무결성

### REQ-AIV-005 — 시스템 지시 우회 시도 방어 ⚠️ 부분 구현

**요구사항:** 학습자 입력에 포함된 시스템 지시 우회 시도에 대한 방어 조치를 강구하여야 하며, 인젝션 시도에 대해 행동 규약(REQ-AIV-008, 009)을 유지하여야 한다.

**현재 구현:** 별도의 인젝션 탐지·차단 코드는 없다. 방어는 프롬프트 구조 수준에서 이루어진다.

1. 학습자 메시지는 시스템 프롬프트와 분리된 `user` 역할 메시지로 전달된다.
2. 시스템 프롬프트는 `resolvePrompt()`에서 템플릿 치환으로 고정된다.
3. 학습자 입력이 직접 시스템 프롬프트를 수정할 수 없다.

**미구현 사항:** 인젝션 시도 패턴 탐지 및 차단 로직 없음. 인젝션 패턴 테스트셋 기반 위반율 측정 미수행.

**검증 방법:** 인젝션 시도 패턴 테스트셋을 입력으로 전송해 응답이 행동 규약을 준수하는지 검증. 위반율 임계값은 `[TBD]`.

## 5.4.2.4 출력 검증

### REQ-AIV-006 — 질문 유형 분류기 출력 검증 ✅

**요구사항:** 질문 유형 분류기는 정의된 6종 외의 값을 출력하지 아니하여야 하며, 분류 실패 시 안전한 기본 유형으로 폴백하여야 한다.

**구현:** `QuestionTypeRouter.parseType()`의 3단계 폴백 구조.

```
1. 코드 블록 있음 → TYPE_E (LLM 호출 없음)
2. TYPE_C + RAG 없음 → TYPE_A
3. LLM 응답이 6종 외의 값 또는 매칭 실패 → TYPE_A (기본값)
```

`QuestionType.values()` 순회에서 매칭되지 않으면 무조건 TYPE_A를 반환하므로 정의되지 않은 유형이 출력될 수 없다.

**검증:** `NoteMetadataExtractorTest.java`, `RagRetrievalServiceTest.java` 단위 테스트로 폴백 동작 검증 완료.

---

### REQ-AIV-007 — 외부 LLM 빈 응답·오류 처리 ⬜ 미구현

**요구사항:** 외부 LLM 응답이 빈 값이거나 오류인 경우, 시스템은 학습자에게 재시도 안내 메시지를 반환하여야 한다.

**현재 상태:** `chatClient.prompt()...call()` 호출에 try-catch 없음. LLM 오류 시 `GlobalExceptionHandler`가 500을 반환한다.

| DRD 명세 | 현재 동작 | HTTP 코드 |
|---|---|---|
| LLM 타임아웃·오류 | 500 반환 | 502여야 함 |
| 빈 응답 | 500 반환 | 200 + 재질문 유도여야 함 |

**개선 방향:** LLM 호출을 try-catch로 감싸고 예외 유형별로 적절한 응답 반환 로직 추가.

## 5.4.2.5 AI 튜터 행동 규약

### REQ-AIV-008 — 정답 미포함 ⚠️ 위반율 임계 기반 검증 필요

**요구사항:** AI 튜터 응답에는 완성된 코드 또는 직접적 정답이 포함되어서는 아니된다.

**구현:** 시스템 프롬프트의 Iron Rules와 TYPE별 제약 조건으로 LLM에 지시.

**한계:** LLM 출력은 확률적이므로 100% 보장 불가. 위반율 임계 기반 모니터링이 필요하다.

**검증 방법:** 정답을 요구하는 명시적 발화(예: "정답 알려줘", "코드 완성해줘") 전송 후 응답 내 정답 포함 여부 수동 검수. 위반율 임계값 `[TBD]`.

---

### REQ-AIV-009 — 단일 질문 ⚠️ 위반율 임계 기반 검증 필요

**요구사항:** 하나의 응답에 두 개 이상의 질문이 포함되어서는 아니된다 (요약 응답 모드 제외).

**구현:** 시스템 프롬프트에 "한 응답에 정확히 하나의 질문만을 포함하여야 한다" 지시.

**검증 방법:** 응답 내 의문문 수 카운팅으로 자동화 가능. `?` 또는 의문형 종결어미 패턴 감지. 위반율 임계값 `[TBD]`.

**REQ-AIV-008 vs 009 비교:**

| | REQ-AIV-008 (정답 미포함) | REQ-AIV-009 (단일 질문) |
|---|---|---|
| 검증 자동화 | 어려움 — 의미 판단 필요 | 가능 — 의문문 카운팅 |
| 검증 주체 | 수동 검수 또는 LLM 판정자 | 자동화 스크립트 |

## 5.4.2.6 검색 품질 임계

### REQ-AIV-011 — 관련 노트 검색 재현율 목표 ✅ 측정 완료

**요구사항:** 관련 노트 검색 재현율은 정의된 테스트 데이터셋 기준 목표치 이상을 유지하여야 한다. 임계값 또는 검색 정책 변경 시 회귀 재현율 측정을 수행하여야 한다.

**이슈별 측정 이력:**

| 이슈 | 변경 사항 | 측정 결과 |
|---|---|---|
| #57 | NotePreprocessor 전처리 제거 | Recall@4 40% → 100% (+60%p) |
| #60 | similarity-threshold 0.75 → 0.55 | Dense 평균 반환 0건 → 5.8건 |
| #62 | Dense-only → 하이브리드 (Dense+Sparse+RRF) | Recall@4 0.18 → 0.43 (+0.25) |

**목표치 수치:** `[TBD]` — 측정 실험으로 효과는 확인했으나 공식 목표치는 미확정.

**회귀 측정 의무:** `similarity-threshold` 또는 검색 정책 변경 시 반드시 Recall@4 재측정 수행. 측정 절차는 `docs/테스트/하이브리드_Recall_측정_절차.md` 참조.

## 위반율 임계 기반 모니터링 — 공통 설명

외부 LLM의 출력은 확률적이기 때문에 "항상 100% 준수"를 보장할 수 없다. REQ-AIV-008, 009처럼 LLM 출력에 의존하는 요구사항은 위반율 임계 기반 통계적 검증 방식을 사용한다.

**검증 절차:**
1. 테스트셋 N개 발화를 실제 API에 전송
2. 위반 횟수 / N = 위반율 계산
3. 위반율이 임계값 이하이면 통과, 초과 시 프롬프트 정책 재검토

**REQ-AIV-010은 예외:** `MAX_QUESTIONS` 상수로 결정론적으로 동작하므로 위반율 모니터링 대상이 아니다.
