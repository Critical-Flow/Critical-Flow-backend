## 6.1 성능 요구사항

### 6.1.1 응답시간

#### Q. AI 튜터 응답시간 목표를 15초로 잡은 근거는?

AI-001(AI 튜터 응답 생성) 요청 처리 흐름에서 소요 시간을 합산한 결과다.

| 처리 단계 | 예상 소요 시간 |
|---|---|
| RAG 검색 (ChromaDB Dense 호출) | ~200–300ms |
| RAG 검색 (ChromaDB Sparse 호출) | ~200–300ms |
| RRF 병합 + 2차 필터 (Java 내부) | ~10ms |
| gpt-4o API 호출 (프롬프트 전송 ~ 응답 수신) | 3–10초 |
| DB 조회 및 저장 | ~50–100ms |
| **합계 (P90 추정)** | **~4–11초** |

gpt-4o는 프롬프트 길이, 응답 길이, OpenAI 서버 부하에 따라 변동이 크다. 10초 목표는 평상시에는 달성 가능하지만 피크 시에는 초과할 수 있으므로 P90 기준 15초로 설정했다.

**기능 유형별 응답시간 목표:**

| 기능 유형 | 측정 대상 | 목표 (P90) |
|---|---|---|
| AI 튜터 응답 생성 (AI-001) | 요청 수신 ~ 응답 본문 반환 | **15초 이하** |
| 노트 임베딩 (AI-003) | 노트 저장 ~ 임베딩 완료 | **3초 이하** |
| 일반 API (노트 CRUD, 대화 조회) | 요청 수신 ~ 응답 반환 | **1초 이하** |

**타임아웃 동작 (미구현):** LLM 응답이 타임아웃되는 경우 502 Bad Gateway와 재시도 안내 메시지를 반환해야 한다. 현재 try-catch 없어 500이 반환된다.

### 6.1.2 처리량

#### Q. 처리량 목표의 상한이 코드가 아닌 OpenAI Rate Limit인 이유는?

시스템 자체에 Rate Limit 로직이 없다. AI 기능 요청 1건마다 OpenAI API를 1회 이상 호출하므로, 사실상 처리량 상한은 가입한 OpenAI 요금제의 **RPM(Requests Per Minute)** 한도가 결정한다.

**AI-001 요청 1건당 OpenAI API 호출 수:**
- 코드 블록이 있는 노트: gpt-4o 1회 (질문 유형 분류 규칙 기반, 응답 생성 1회)
- 코드 블록이 없는 노트: gpt-4o 2회 (질문 유형 분류 1회 + 응답 생성 1회)

**처리량 목표:**

| 구분 | 목표 | 비고 |
|---|---|---|
| AI 튜터 응답 생성 (AI-001) | 분당 10건 이상 | OpenAI API Rate Limit 이내 |
| 노트 임베딩 (AI-003) | 분당 30건 이상 | OpenAI Embedding API Rate Limit 이내 |
| 일반 API | 분당 100건 이상 | DB + 애플리케이션 서버 처리 기준 |

요금제 변경 시 RPM 한도가 달라지므로 수치를 재확인해야 한다.

### 6.1.3 동시 사용자 수

**목표:**

| 구분 | 목표 |
|---|---|
| 평상시 동시 접속자 | 10명 |
| 최대 피크 동시 접속자 | 30명 |

**피크 초과 시 동작:** 503 Service Unavailable 반환. 대기열 처리는 현재 범위에 포함하지 않는다.

**AI-001 동시 처리 특성:** gpt-4o 응답 대기 시간이 길어 1인당 커넥션 점유 시간이 길다. 동시 접속자 30명 기준으로 AI 튜터 요청이 집중되면 OpenAI API 호출이 병렬로 발생해 처리량 목표(분당 10건)와 상충될 수 있다. 운영 측정 후 목표값을 재확정해야 한다.

## 6.2 가용성 및 신뢰성 요구사항

### 6.2.1 가용성 목표 (Uptime)

| 구분 | 목표 |
|---|---|
| 시스템 가용률 | **월간 95% 이상** |

가용률 95%는 월간 약 36시간의 다운타임을 허용한다. AI 기능은 외부 OpenAI API에 의존하므로, OpenAI 서비스 장애 시간은 시스템 가용률 측정에서 제외한다.

---

### 6.2.2 복구 목표 (RTO / RPO)

| 지표 | 목표 | 설명 |
|---|---|---|
| RTO (복구 시간 목표) | **2시간 이내** | 장애 발생 후 서비스 정상화까지 최대 허용 시간 |
| RPO (복구 시점 목표) | **24시간 이내** | 장애 발생 시 허용 가능한 최대 데이터 손실 범위 |

**RTO 근거:** 단일 인스턴스 재시작 또는 재배포로 복구 가능한 수준. 자동 복구 메커니즘은 구현되어 있지 않으며, 수동 개입을 전제로 한다.

**RPO 근거:** 학습 노트·대화 기록은 MySQL에 저장되어 있고, 임베딩 벡터는 ChromaDB에 저장된다. 주기적 백업 정책은 `[TBD]`.

#### Q. RPO 복구 수단이 있는가?

임베딩 손실 시 `POST /api/notes/reembed` 엔드포인트로 전체 재임베딩이 가능하다. 노트·대화 기록 원본은 MySQL에 저장되므로 DB 백업이 있으면 데이터 복구 후 재임베딩으로 ChromaDB를 재구성할 수 있다.

```
복구 절차:
1. MySQL 백업으로 노트·대화 데이터 복원
2. POST /api/notes/reembed 호출 → 전체 노트 재임베딩
3. ChromaDB criticalflow-notes 컬렉션 재구성 완료
```

### 6.2.3 부분 장애 시 동작

#### 외부 LLM 서비스 장애 (OpenAI API)

| 장애 유형 | DRD 명세 동작 | 현재 구현 상태 |
|---|---|---|
| LLM 응답 타임아웃 | 502 + 재시도 안내 | ⬜ **미구현** (500 반환) |
| LLM 빈 응답 수신 | 200 + 재질문 유도 | ⬜ **미구현** (500 반환) |
| LLM 그 외 오류 | 502 + 재시도 안내 | ⬜ **미구현** (500 반환) |

LLM 장애 시 AI 튜터 응답 생성(AI-001)은 중단되나, 노트 CRUD·대화 조회 등 LLM 비의존 기능은 정상 동작해야 한다.

**미구현 원인:** `chatClient.prompt()...call()` 호출에 try-catch 없음. `GlobalExceptionHandler`가 모든 예외를 500으로 처리한다.

---

#### 관련 노트 검색 장애 (ChromaDB)

| 장애 유형 | DRD 명세 동작 | 현재 구현 상태 |
|---|---|---|
| ChromaDB 검색 오류 | 빈 컨텍스트 반환 + AI-001 계속 수행 | ⬜ **미구현** (500 반환) |
| ChromaDB 임베딩 저장 오류 | 노트 저장 성공 + 임베딩 실패 로깅 | ⬜ **미구현** (트랜잭션 롤백으로 노트 저장도 실패) |

RAG 검색은 AI 튜터의 보조 컨텍스트이므로, 검색 장애가 전체 응답 생성을 중단시켜서는 안 된다.

**미구현 원인:**
- `RagRetrievalService`에 try-catch 없음 → ChromaDB 오류 시 예외 전파 → 500
- `NoteService.saveNote()`에서 `noteEmbeddingService.embed()`가 예외를 던지면 `@Transactional`로 인해 노트 DB 저장도 롤백됨

**개선 방향:**

```java
// RagRetrievalService 개선 방향
try {
    List<Document> denseResults = denseSearch(queryText, userId, excludeNoteId);
    List<Document> sparseResults = sparseSearch(queryText, userId, excludeNoteId);
    ...
} catch (Exception e) {
    log.error("ChromaDB 검색 오류. 빈 컨텍스트로 계속 진행.", e);
    return RagContext.builder().chunks(List.of()).build();
}

// NoteService 개선 방향
StudyNote saved = noteRepository.save(note);  // 노트 저장 먼저
try {
    noteEmbeddingService.embed(saved);          // 임베딩 별도 처리
} catch (Exception e) {
    log.error("임베딩 저장 실패. noteId={}", saved.getNoteId(), e);
}
return NoteResponse.from(saved);              // 노트 저장은 성공 처리
```
