# 6.1 성능 요구사항 (Performance)

본 절은 시스템이 만족하여야 할 성능 목표를 정의한다. 수치는 단일 인스턴스 기준이며, 외부 LLM 서비스(OpenAI) 및 벡터 스토어(ChromaDB)의 가용성이 정상인 상태를 전제로 한다.

---

## 6.1.1 응답시간

### 기능 유형별 응답시간 목표

| 기능 유형 | 측정 대상 | 목표 (P90) | 비고 |
|---|---|---|---|
| AI 튜터 응답 생성 (AI-001) | 요청 수신 ~ 응답 본문 반환 | 15초 이하 | LLM 호출(gpt-4o) + RAG 검색(ChromaDB 2회) 포함 |
| 노트 임베딩 (AI-003, 저장 시) | 노트 저장 요청 ~ 임베딩 완료 | 3초 이하 | OpenAI Embedding API 호출 포함 |
| 일반 API (노트 CRUD, 대화 조회 등) | 요청 수신 ~ 응답 반환 | 1초 이하 | 외부 LLM 호출 없는 경우 |

> **AI-001 응답시간 근거:** RAG 검색(dense + sparse, ChromaDB 2회 호출) ~500ms + gpt-4o API 호출 ~3–10초. 프롬프트 길이 및 OpenAI 서버 상태에 따라 변동.

> **AI-001 타임아웃 동작:** 외부 LLM 응답이 타임아웃되는 경우, 시스템은 학습자에게 재시도 안내 메시지를 반환하여야 한다 (502 Bad Gateway). 타임아웃 임계값은 [TBD: 운영 측정 후 확정].

## 6.1.2 처리량

| 구분 | 목표 | 비고 |
|---|---|---|
| AI 튜터 응답 생성 (AI-001) | 분당 10건 이상 | OpenAI API 요금제 Rate Limit 이내 |
| 노트 임베딩 (AI-003) | 분당 30건 이상 | OpenAI Embedding API Rate Limit 이내 |
| 일반 API | 분당 100건 이상 | DB + 애플리케이션 서버 처리 기준 |

> **처리량 제약:** AI 기능의 처리량 상한은 시스템 자체보다 OpenAI API Rate Limit에 의해 결정된다. 요금제 변경 시 수치를 재확인하여야 한다.

---

## 6.1.3 동시 사용자 수

| 구분 | 목표 |
|---|---|
| 평상시 동시 접속자 | 10명 |
| 최대 피크 동시 접속자 | 30명 |

> **피크 초과 시 외부 동작:** 동시 접속자가 최대 피크를 초과하는 경우, 시스템은 신규 요청에 대해 503 Service Unavailable을 반환하여야 한다. 대기열 처리는 현재 범위에 포함되지 아니한다.

> **AI-001 동시 처리 특성:** gpt-4o 응답 대기 시간이 길어 1인당 커넥션 점유 시간이 길다. 동시 접속자 30명 기준, AI 튜터 요청이 집중될 경우 OpenAI API 호출이 병렬로 발생한다. 이 경우 처리량 목표(분당 10건)와의 상충이 발생할 수 있으며, 운영 측정 후 목표값을 재확정한다.
