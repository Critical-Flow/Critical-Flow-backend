# Critical Flow 배포 가이드

> **이 문서의 목표:** AWS, Docker, 리눅스를 전혀 모르는 사람도 이 문서만 보고 배포를 완료할 수 있도록 모든 과정을 빠짐없이 설명합니다.
>
> **서버 환경:** AWS EC2 (Ubuntu 22.04 LTS) + Docker + GitHub Actions 자동 배포
>
> **예상 소요 시간:** 처음 하는 경우 2~3시간

---

## 시작 전 준비물 체크리스트

아래 항목을 모두 준비한 후 시작하세요.

- [ ] **AWS 계정** — [aws.amazon.com](https://aws.amazon.com)에서 가입 (신용카드 필요)
- [ ] **도메인** — 가비아, Namecheap 등에서 구매 (HTTPS를 위해 필수, 연 1~2만원)
- [ ] **GitHub 계정** — 저장소 Admin 권한 보유
- [ ] **ChromaDB 서버 IP와 포트** — 팀원에게 확인
- [ ] **GitHub OAuth App Client ID / Secret** — 아래 [부록 A](#부록-a-github-oauth-app-생성) 참고
- [ ] **OpenAI API Key** — [platform.openai.com](https://platform.openai.com)에서 발급

## PART 1. AWS EC2 서버 생성

### 1-1. AWS 콘솔 접속 및 지역 설정

1. [console.aws.amazon.com](https://console.aws.amazon.com) 접속 후 로그인

2. 화면 **오른쪽 상단**에 지역 선택 드롭다운이 있습니다.
   **`아시아 태평양 (서울) ap-northeast-2`** 를 선택하세요.

   > 서울 리전을 선택해야 한국에서 접속할 때 속도가 빠릅니다.

3. 검색창에 `EC2` 입력 → **EC2** 클릭

---

### 1-2. EC2 인스턴스 생성

1. 왼쪽 메뉴 → **인스턴스** → 오른쪽 상단 **인스턴스 시작** 버튼 클릭

2. **이름 및 태그** 섹션
   - 이름: `critical-flow-server` 입력

3. **애플리케이션 및 OS 이미지 (AMI)** 섹션
   - **Ubuntu** 탭 클릭
   - **Ubuntu Server 22.04 LTS (HVM), SSD Volume Type** 선택
   - 아키텍처: `64비트(x86)` 선택

   > ⚠️ 22.04 LTS인지 반드시 확인하세요. 24.04가 기본 선택되어 있을 수 있습니다.

4. **인스턴스 유형** 섹션
   - 검색창에 `t2.small` 입력 후 선택
   - 사양 확인: `1 vCPU`, `2 GiB 메모리`

5. **키 페어(로그인)** 섹션
   - **새 키 페어 생성** 클릭
   - 키 페어 이름: `critical-flow-key` 입력
   - 키 페어 유형: `RSA`
   - 프라이빗 키 파일 형식:
     - Mac / Linux 사용자: `.pem`
     - Windows 사용자: `.ppk` (PuTTY 사용 시) 또는 `.pem` (Windows 10 이상 PowerShell 사용 시 `.pem` 권장)
   - **키 페어 생성** 클릭 → `.pem` 파일이 자동으로 다운로드됩니다

   > ⚠️ **중요:** 이 `.pem` 파일은 서버 접속의 열쇠입니다. 절대 분실하지 마세요.
   > 분실 시 해당 서버에 영구적으로 접속 불가능합니다.
   > `~/Downloads/` 폴더에서 안전한 곳으로 이동해두세요.

6. **네트워크 설정** 섹션
   - **편집** 버튼 클릭
   - 아래 표대로 보안 그룹 규칙을 설정합니다

   기본으로 SSH 규칙 하나가 있습니다. 아래 두 개를 **보안 그룹 규칙 추가** 버튼으로 추가하세요:

   | 유형 | 포트 범위 | 소스 유형 | 설명 |
   |---|---|---|---|
   | SSH | 22 | 내 IP | 서버 접속용 (자동으로 내 IP 입력됨) |
   | HTTP | 80 | 위치 무관 (0.0.0.0/0) | HTTPS 리다이렉트 수신 |
   | HTTPS | 443 | 위치 무관 (0.0.0.0/0) | 실제 API 트래픽 |

   > SSH의 소스 유형을 `내 IP`로 설정하면 현재 내 컴퓨터 IP만 접속 가능합니다.
   > 카페 등 다른 네트워크에서 접속해야 한다면 그때마다 보안그룹에서 IP를 추가해야 합니다.

7. **스토리지 구성** 섹션
   - 기본값 `8 GiB gp3` 유지
   - 변경하지 않아도 됩니다

8. **요약** 섹션에서 설정 최종 확인 후 **인스턴스 시작** 클릭

9. 성공 화면이 나오면 **인스턴스 보기** 클릭

   인스턴스 상태가 `실행 중` 이 되면 서버가 준비된 것입니다. (보통 1~2분 소요)

---

### 1-3. 퍼블릭 IP 확인

1. 인스턴스 목록에서 `critical-flow-server` 클릭
2. 아래 **세부 정보** 탭에서 **퍼블릭 IPv4 주소** 확인
   - 예시: `13.125.xxx.xxx`
3. 이 IP를 메모해두세요 (이후 여러 곳에서 사용)

## PART 2. EC2 서버에 개발 환경 설치

### 2-1. SSH로 서버 접속

**Mac / Linux 사용자:**

터미널(Terminal)을 열고 아래 명령어 실행:

```bash
# 1. .pem 파일 권한을 읽기 전용으로 변경 (필수, 이 설정 없으면 접속 거부됨)
chmod 400 ~/Downloads/critical-flow-key.pem

# 2. 서버 접속 (IP는 1-3에서 확인한 퍼블릭 IP로 변경)
ssh -i ~/Downloads/critical-flow-key.pem ubuntu@13.125.xxx.xxx
```

> Ubuntu 22.04는 기본 유저명이 `ec2-user`가 아닌 **`ubuntu`** 입니다.

**Windows 사용자 (PowerShell):**

PowerShell을 열고 아래 명령어 실행:

```powershell
# 서버 접속
ssh -i C:\Users\사용자명\Downloads\critical-flow-key.pem ubuntu@13.125.xxx.xxx
```

처음 접속 시 아래 메시지가 나옵니다:
```
The authenticity of host '13.125.xxx.xxx' can't be established.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```
`yes` 입력 후 Enter

접속 성공 시 아래와 같이 표시됩니다:
```
Welcome to Ubuntu 22.04.x LTS (GNU/Linux ...)

ubuntu@ip-xxx-xxx-xxx-xxx:~$
```

이제부터 `ubuntu@ip-xxx:~$` 로 시작하는 명령어는 모두 **이 서버 안에서 실행**하는 명령어입니다.

### 2-3. Docker 설치

Ubuntu에 Docker를 공식 방법으로 설치합니다. 아래 명령어를 **한 줄씩** 실행하세요:

```bash
# 1. Docker 설치에 필요한 패키지 설치
sudo apt install -y ca-certificates curl gnupg lsb-release

# 2. Docker 공식 GPG 키 추가
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# 3. Docker 저장소 등록
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 4. 패키지 목록 업데이트
sudo apt update

# 5. Docker 설치
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 6. ubuntu 유저가 sudo 없이 docker 명령어 사용할 수 있도록 권한 부여
sudo usermod -aG docker ubuntu

# 7. 서버 재시작 시 Docker 자동 실행 설정
sudo systemctl enable docker

# 8. 권한 적용을 위해 서버에서 로그아웃
exit
```

## PART 3. 도메인 연결 및 고정 IP 설정

### 3-1. Elastic IP (고정 IP) 발급

기본 EC2의 퍼블릭 IP는 서버를 **재시작할 때마다 바뀝니다.** 도메인과 연결하려면 절대 안 됩니다.
고정 IP(Elastic IP)를 발급받아 연결해야 합니다.

1. AWS 콘솔 → EC2 → 왼쪽 메뉴 스크롤 → **네트워크 및 보안** → **탄력적 IP** 클릭
2. 오른쪽 상단 **탄력적 IP 주소 할당** 클릭
3. 모든 설정을 기본값 유지 → **할당** 클릭
4. 할당된 IP 주소가 목록에 보입니다 (예: `13.125.yyy.yyy`)
5. 해당 IP 체크박스 선택 → **작업** 버튼 → **탄력적 IP 주소 연결** 클릭
6. 인스턴스: `critical-flow-server` 선택
7. 프라이빗 IP 주소: 자동으로 채워짐 (그대로 두기)
8. **연결** 클릭

> ✅ 이제 이 Elastic IP가 서버의 영구 주소입니다.
> 앞으로 서버 IP는 이 주소를 사용하세요.
>
> ⚠️ Elastic IP는 EC2 인스턴스에 **연결된 상태**에서는 무료입니다.
> 인스턴스를 삭제하거나 연결 해제하면 비용이 발생하니 주의하세요.

---

### 3-2. 도메인 DNS A레코드 등록

도메인을 구매한 사이트(가비아, Namecheap 등)의 **DNS 관리** 페이지로 이동합니다.

**가비아 기준:**
1. [gabia.com](https://gabia.com) 로그인 → My가비아 → 서비스 관리 → 도메인 관리 → DNS 정보 → DNS 관리

**등록할 레코드:**

| 타입 | 호스트 | 값(IP) | TTL |
|---|---|---|---|
| A | `@` | Elastic IP 주소 | 300 |
| A | `api` | Elastic IP 주소 | 300 |

- `@` 는 루트 도메인 (예: `criticalflow.com`)
- `api` 는 서브도메인 (예: `api.criticalflow.com`)
- 둘 중 사용할 도메인 형태로 등록하면 됩니다 (보통 `api` 서브도메인 권장)

**DNS 적용 확인** (내 PC 터미널에서, EC2 서버 아님):

```bash
nslookup api.criticalflow.com
```

출력에 설정한 Elastic IP가 보이면 DNS 연결 성공입니다.
DNS 전파는 최대 30분 소요될 수 있습니다. 바로 안 나오면 잠시 후 다시 시도하세요.

## PART 4. GitHub 저장소 설정

### 4-1. GitHub Secrets 등록

GitHub Actions가 서버에 배포할 때 필요한 민감한 정보(비밀번호, API 키 등)를 GitHub Secrets에 등록합니다.
코드에 직접 넣으면 절대 안 됩니다.

**접근 경로:**
GitHub 저장소 → **Settings** 탭 → 왼쪽 메뉴 **Secrets and variables** → **Actions** → **New repository secret** 버튼

아래 목록의 Secret을 하나씩 등록합니다. Name과 Secret 값을 정확히 입력하고 **Add secret** 클릭:

---

**① EC2_HOST**
- Name: `EC2_HOST`
- Secret: 방금 발급한 Elastic IP 주소
- 예시: `13.125.yyy.yyy`

**② EC2_USER**
- Name: `EC2_USER`
- Secret: `ubuntu`
- Ubuntu 22.04의 기본 유저명입니다. 그대로 입력하세요.

**③ EC2_SSH_KEY**
- Name: `EC2_SSH_KEY`
- Secret: `.pem` 파일의 내용 전체

  내 PC 터미널에서 아래 명령어로 내용을 확인 후 전체 복사:
  ```bash
  cat ~/Downloads/critical-flow-key.pem
  ```
  `-----BEGIN RSA PRIVATE KEY-----` 부터 `-----END RSA PRIVATE KEY-----` 까지 전부 복사하여 붙여넣기

**④ DB_USERNAME**
- Name: `DB_USERNAME`
- Secret: `criticalflow`
- MySQL에 생성할 데이터베이스 유저명입니다.

**⑤ DB_PASSWORD**
- Name: `DB_PASSWORD`
- Secret: 강력한 비밀번호 직접 설정
- 예시: `Cf2024!Secure#Pass`
- 영문 대소문자 + 숫자 + 특수문자 조합, 12자 이상 권장

**⑥ DB_ROOT_PASSWORD**
- Name: `DB_ROOT_PASSWORD`
- Secret: MySQL root 비밀번호 (DB_PASSWORD와 다르게 설정)
- 예시: `Root2024!Master#Key`

**⑦ JWT_SECRET**
- Name: `JWT_SECRET`
- Secret: 32자 이상의 랜덤 문자열

  아래 명령어로 생성 가능 (내 PC 터미널):
  ```bash
  openssl rand -base64 32
  ```
  출력된 문자열을 그대로 사용

**⑧ OPENAI_API_KEY**
- Name: `OPENAI_API_KEY`
- Secret: OpenAI API 키
- 예시: `sk-proj-xxxxxxxxxxxxxxxxxxxxxx`

**⑨ GITHUB_CLIENT_ID**
- Name: `GITHUB_CLIENT_ID`
- Secret: GitHub OAuth App의 Client ID
- 발급 방법은 [부록 A](#부록-a-github-oauth-app-생성) 참고

**⑩ GITHUB_CLIENT_SECRET**
- Name: `GITHUB_CLIENT_SECRET`
- Secret: GitHub OAuth App의 Client Secret

**⑪ CHROMA_HOST**
- Name: `CHROMA_HOST`
- Secret: ChromaDB 서버 주소 (팀원에게 확인)
- 예시: `http://192.168.x.x` 또는 `http://팀원서버도메인`

**⑫ CHROMA_PORT**
- Name: `CHROMA_PORT`
- Secret: `8000`

**⑬ FRONTEND_CALLBACK_URL**
- Name: `FRONTEND_CALLBACK_URL`
- Secret: 프론트엔드 OAuth 콜백 URL
- 예시: `https://criticalflow.com/oauth/callback`

**⑭ DOMAIN**
- Name: `DOMAIN`
- Secret: 사용할 도메인 (앞에 https:// 없이)
- 예시: `api.criticalflow.com`

총 14개 등록 완료 후 목록에서 모두 확인하세요.

## PART 5. 프로젝트 코드 파일 작성 및 Push

> 이 파트의 모든 작업은 **내 PC**에서 로컬 저장소에 진행합니다.

### 5-1. Dockerfile 작성

프로젝트 루트 디렉토리에 `Dockerfile` 파일을 생성합니다:

```dockerfile
# ─── Stage 1: 빌드 ──────────────────────────────────────────────
# JDK 17이 포함된 경량 이미지로 JAR 파일을 빌드합니다
FROM eclipse-temurin:17-jdk-alpine AS builder

WORKDIR /app

# 의존성 캐시 레이어 (소스 변경과 별도로 캐싱됨)
COPY gradlew .
COPY gradle gradle
COPY build.gradle .
COPY settings.gradle .
RUN chmod +x gradlew && ./gradlew dependencies --no-daemon

# 소스 코드 복사 후 빌드 (테스트 제외 — CI에서 이미 통과)
COPY src src
RUN ./gradlew bootJar --no-daemon -x test

# ─── Stage 2: 실행 ──────────────────────────────────────────────
# JRE만 포함된 경량 이미지로 실행 (빌드 도구 제외, 이미지 크기 절감)
FROM eclipse-temurin:17-jre-alpine

WORKDIR /app

# 보안: root 대신 전용 유저로 실행
RUN addgroup -S spring && adduser -S spring -G spring
USER spring

# 빌드 결과물(JAR)만 복사
COPY --from=builder /app/build/libs/*.jar app.jar

EXPOSE 8080

ENTRYPOINT ["java", "-jar", "app.jar"]
```

### 5-2. Nginx 설정 파일 작성

`nginx/` 폴더를 만들고 `nginx/default.conf` 파일을 생성합니다:

> ⚠️ `api.criticalflow.com` 부분을 본인 도메인으로 전부 변경하세요.

```nginx
# HTTP로 들어오면 HTTPS로 리다이렉트
server {
    listen 80;
    server_name api.criticalflow.com;

    location / {
        return 301 https://$host$request_uri;
    }
}

# HTTPS 처리 및 Spring Boot로 프록시
server {
    listen 443 ssl;
    server_name api.criticalflow.com;

    # SSL 인증서 경로 (Let's Encrypt가 자동으로 생성)
    ssl_certificate /etc/letsencrypt/live/api.criticalflow.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.criticalflow.com/privkey.pem;

    # 보안 설정
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers on;
    ssl_session_cache shared:SSL:10m;

    # 요청을 Spring Boot 컨테이너로 전달
    location / {
        proxy_pass http://app:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }
}
```

### 5-3. docker-compose.yml 작성

프로젝트 루트에 `docker-compose.yml` 파일을 생성합니다:

> ⚠️ `ghcr.io/critical-flow/critical-flow-backend:latest` 의 `critical-flow` 부분을
> 본인 GitHub 조직명 또는 유저명으로 변경하세요. (소문자만 사용)

```yaml
services:

  # ── Nginx: 외부 요청 진입점, HTTPS 처리 ──────────────────────
  nginx:
    image: nginx:alpine
    container_name: criticalflow-nginx
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/default.conf:/etc/nginx/conf.d/default.conf:ro
      - certbot-etc:/etc/letsencrypt:ro
    depends_on:
      - app
    restart: always
    networks:
      - criticalflow-net

  # ── Spring Boot 앱 ──────────────────────────────────────────
  app:
    image: ghcr.io/critical-flow/critical-flow-backend:latest
    container_name: criticalflow-app
    env_file:
      - .env
    depends_on:
      db:
        condition: service_healthy
    restart: always
    networks:
      - criticalflow-net

  # ── MySQL 데이터베이스 ────────────────────────────────────────
  db:
    image: mysql:8.0
    container_name: criticalflow-db
    environment:
      MYSQL_DATABASE: criticalflow
      MYSQL_USER: ${DB_USERNAME}
      MYSQL_PASSWORD: ${DB_PASSWORD}
      MYSQL_ROOT_PASSWORD: ${DB_ROOT_PASSWORD}
    volumes:
      # named volume 사용 → 컨테이너 삭제/재시작해도 데이터 유지됨
      - criticalflow-mysql-data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-u", "root", "-p${MYSQL_ROOT_PASSWORD}"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s
    restart: always
    networks:
      - criticalflow-net

# ── 볼륨 (데이터 영속성) ─────────────────────────────────────────
volumes:
  criticalflow-mysql-data:   # MySQL 데이터 저장 (컨테이너와 독립적으로 유지)
  certbot-etc:               # SSL 인증서 저장

# ── 네트워크 ─────────────────────────────────────────────────────
networks:
  criticalflow-net:
    driver: bridge
```

### 5-5. GitHub Actions 워크플로우 작성

`.github/workflows/deploy.yml` 파일을 생성합니다:

```yaml
name: CI/CD 자동 배포

# main 브랜치에 push될 때만 실행
on:
  push:
    branches: [ main ]

jobs:
  # ── Job 1: 빌드 & Docker 이미지 push ──────────────────────────
  build-and-push:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write   # GHCR push 권한

    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: JDK 17 설정
        uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: 'temurin'

      - name: Gradle 캐시 복원 (빌드 속도 최적화)
        uses: actions/cache@v4
        with:
          path: |
            ~/.gradle/caches
            ~/.gradle/wrapper
          key: ${{ runner.os }}-gradle-${{ hashFiles('**/*.gradle*') }}
          restore-keys: ${{ runner.os }}-gradle-

      - name: Gradle 빌드 및 테스트
        run: ./gradlew build --no-daemon

      - name: GHCR 로그인
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Docker 이미지 빌드 및 GHCR Push
        uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          tags: |
            ghcr.io/${{ github.repository_owner }}/critical-flow-backend:latest
            ghcr.io/${{ github.repository_owner }}/critical-flow-backend:sha-${{ github.sha }}

  # ── Job 2: EC2 배포 (Job 1 성공 후 실행) ──────────────────────
  deploy:
    needs: build-and-push
    runs-on: ubuntu-latest

    steps:
      - name: EC2 SSH 접속 및 배포
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.EC2_HOST }}
          username: ${{ secrets.EC2_USER }}
          key: ${{ secrets.EC2_SSH_KEY }}
          script: |
            cd /home/ubuntu/critical-flow

            # GitHub Secrets 값으로 .env 파일 갱신
            cat > .env << 'ENVEOF'
            DB_USERNAME=${{ secrets.DB_USERNAME }}
            DB_PASSWORD=${{ secrets.DB_PASSWORD }}
            DB_ROOT_PASSWORD=${{ secrets.DB_ROOT_PASSWORD }}
            DB_URL=jdbc:mysql://db:3306/criticalflow?useSSL=false&serverTimezone=Asia/Seoul&characterEncoding=UTF-8
            JWT_SECRET=${{ secrets.JWT_SECRET }}
            JWT_EXPIRATION=3600000
            JWT_REFRESH_EXPIRATION=1209600000
            OPENAI_API_KEY=${{ secrets.OPENAI_API_KEY }}
            GITHUB_CLIENT_ID=${{ secrets.GITHUB_CLIENT_ID }}
            GITHUB_CLIENT_SECRET=${{ secrets.GITHUB_CLIENT_SECRET }}
            CHROMA_HOST=${{ secrets.CHROMA_HOST }}
            CHROMA_PORT=${{ secrets.CHROMA_PORT }}
            FRONTEND_CALLBACK_URL=${{ secrets.FRONTEND_CALLBACK_URL }}
            ENVEOF

            # GHCR에서 최신 app 이미지만 pull
            echo ${{ secrets.GITHUB_TOKEN }} | docker login ghcr.io -u ${{ github.actor }} --password-stdin
            docker compose pull app

            # 컨테이너 재시작 (MySQL 볼륨 유지, 데이터 초기화 없음)
            docker compose up -d

            # 오래된 이미지 정리
            docker image prune -f

      - name: 배포 헬스체크 (30초 후 API 정상 응답 확인)
        run: |
          sleep 30
          curl -f https://${{ secrets.DOMAIN }}/health || exit 1
```

### 6-3. GHCR 로그인 (서버에서 이미지 pull용)

1. GitHub → 오른쪽 상단 프로필 아이콘 → **Settings**

## PART 8. 운영 중 자주 쓰는 명령어

모든 명령어는 EC2 서버의 `/home/ubuntu/critical-flow` 디렉토리에서 실행합니다.

```bash
# ── 상태 확인 ────────────────────────────────────────────────────
# 컨테이너 실행 상태 확인
docker compose ps

# 앱 서버 로그 실시간 보기 (Ctrl+C로 종료)
docker compose logs -f app

# 앱 서버 최근 100줄 로그
docker compose logs app --tail=100

# Nginx 로그 확인
docker compose logs -f nginx

# DB 로그 확인
docker compose logs db --tail=50

# ── 재시작 ───────────────────────────────────────────────────────
# 전체 재시작 (데이터 유지)
docker compose restart

# app 컨테이너만 재시작
docker compose restart app

# ── 수동 배포 ────────────────────────────────────────────────────
# 최신 이미지로 수동 업데이트
docker compose pull app && docker compose up -d

# ── DB 접속 ──────────────────────────────────────────────────────
docker compose exec db mysql -u criticalflow -p criticalflow
# 비밀번호 입력 후 MySQL 프롬프트 진입

# ── 중지 / 삭제 ──────────────────────────────────────────────────
# 모든 컨테이너 중지 (데이터 볼륨 유지)
docker compose stop

# 컨테이너 삭제 (볼륨은 유지, 데이터 안전)
docker compose down
```

> ❌ **절대 금지:** `docker compose down -v`
> `-v` 옵션은 볼륨까지 삭제합니다. MySQL 데이터가 전부 사라집니다.
