## 1. 진행 이유

**1-1. 발견 경위**
`RagRetrievalService.mergeWithRRF()`에서 RRF 공식 `1/(k + rank)`의 상수 `k=60`을 Cormack et al.(2009) 논문 기본값으로 사용하고 있었다. 이 값은 대규모 문서 검색 환경에서 도출된 경험값인데, 이 프로젝트는 사용자당 노트 수십 건, Dense 최대 6개 + Sparse 최대 10개의 소규모 병합 환경이라 적합성 검증이 필요했다.

**1-2. 해결하지 않을 경우 영향**
- k=60이 소규모 환경에서 과도하게 완만한 점수 분포를 만들어 Dense/Sparse 각각의 신호를 희석할 수 있음
- 양쪽 검색에서 모두 등장한 문서가 실제로 항상 Top-1이 되는지 수식으로 보장되지 않으면 RRF의 핵심 원칙 위반

**1-3. 관련 요구사항**
없음 — RRF 알고리즘 내부 동작 검증이며 기능 요구사항과 직접 연결되지 않음.

**k=60 소규모 환경 적합성 수학적 검증**

RRF 공식: `score(d) = Σ 1/(k + rank(d, list))`  (각 리스트에서 해당 문서의 순위로 합산)

소규모 환경 최악 케이스 (Dense 6개, Sparse 6개):
```
k=60 환경에서:

both(F): Dense rank5 + Sparse rank5
  score(F) = 1/(60+6) + 1/(60+6) = 2/66 = 0.03030

denseOnly(A): Dense rank0만 등장
  score(A) = 1/(60+1) = 1/61   = 0.01639

결론: 0.03030 > 0.01639
→ 양쪽 최하위 등장 문서가 단독 최상위 등장 문서를 항상 이긴다 ✓
```

일반화: k=60일 때 양쪽 등장이 항상 우선인 조건:
```
2/(k + N) > 1/(k + 1)

여기서 N = 최대 rank (리스트 크기 - 1)

N=5 (후보 6개), k=60:
  좌변: 2/66 = 0.03030
  우변: 1/61 = 0.01639
  → 0.03030 > 0.01639 ✓ (성립)

N=10 (후보 10+6=16개 극단 케이스), k=60:
  좌변: 2/70 = 0.02857
  우변: 1/61 = 0.01639
  → 0.02857 > 0.01639 ✓ (성립)
```

**핵심 테스트 케이스 코드**

```java
// 케이스 1: 양쪽 최하위 등장 vs 단독 최상위 — k=60 핵심 검증
@Test
@DisplayName("k=60 소규모 환경에서 양쪽 최하위 등장 문서도 단독 Dense 최상위보다 높은 점수를 받는다")
void bothListLastRankStillBeatsDenseOnlyTopWithK60() {
    Document docA = simpleDoc("A");  // Dense rank0
    Document docB = simpleDoc("B");
    Document docC = simpleDoc("C");
    Document docD = simpleDoc("D");
    Document docE = simpleDoc("E");
    Document both = simpleDoc("F"); // Dense rank5 + Sparse rank5

    List<Document> result = mergeWithRRF(
            List.of(docA, docB, docC, docD, docE, both),       // Dense: A=0위, F=5위
            List.of(simpleDoc("G"), simpleDoc("H"), simpleDoc("I"),
                    simpleDoc("J"), simpleDoc("K"), both),       // Sparse: F=5위
            6);

    int bothIndex    = result.indexOf(both);    // F의 최종 순위
    int denseOnlyIdx = result.stream().map(Document::getId).toList().indexOf("A");

    assertThat(bothIndex).isLessThan(denseOnlyIdx);  // F가 A보다 앞에 위치해야 함
}

// 케이스 2: Dense+Sparse 동시 1위 → Top-1 확인
@Test
@DisplayName("Dense와 Sparse 양쪽 1위 문서가 최고 점수를 받아 Top-1이 된다")
void denseAndSparseTop1BecomesFinalTop1() {
    // star: Dense rank0 + Sparse rank0 → 1/(60+1) + 1/(60+1) = 2/61 = 0.03279
    Document star  = simpleDoc("star");
    Document other = simpleDoc("other");

    List<Document> result = mergeWithRRF(
            List.of(star, other),
            List.of(star, other),
            2);

    assertThat(result.get(0).getId()).isEqualTo("star");
}

// 케이스 3: 중복 제거 — 동일 ID가 두 리스트에 있어도 결과에 1번만
@Test
@DisplayName("동일 ID 문서가 Dense와 Sparse에 모두 있어도 결과에 한 번만 포함된다")
void duplicateDocumentDeduplicatedInResult() {
    Document docA = simpleDoc("A");
    Document docB = simpleDoc("B");
    Document docC = simpleDoc("C");

    List<Document> result = mergeWithRRF(
            List.of(docA, docB),
            List.of(docA, docC),  // docA 중복 등장
            4);

    long countA = result.stream().filter(d -> "A".equals(d.getId())).count();
    assertThat(countA).isEqualTo(1);
}

// 케이스 4: limit 파라미터 정확한 결과 수 제한
@Test
@DisplayName("limit 파라미터로 결과 수를 정확히 제한한다")
void respectsLimitParameter() {
    List<Document> dense  = List.of(
            simpleDoc("1"), simpleDoc("2"), simpleDoc("3"), simpleDoc("4"), simpleDoc("5"));
    List<Document> sparse = List.of(
            simpleDoc("6"), simpleDoc("7"), simpleDoc("8"), simpleDoc("9"), simpleDoc("10"));

    assertThat(mergeWithRRF(dense, sparse, 3)).hasSize(3);
    assertThat(mergeWithRRF(dense, sparse, 1)).hasSize(1);
}
```

**3-3. k=60이 소규모 환경에서 안전한 이유 — 논리적 분석**

RRF 공식 `1/(k+rank)`에서 상수 k가 하는 역할:

- **k가 크면**: 점수 차이가 줄어들고 순위 변화에 둔감해진다 (랭크 0과 랭크 10의 점수 차이 감소)
- **k가 작으면**: 1위 문서에 극단적으로 높은 점수를 부여 (랭크 0의 독점적 우세)

k=60이 소규모 환경(후보 6~10개)에서 안전한 이유:

```
소규모(후보 6개) 에서 k=60 시:
  rank0 점수: 1/(60+1) = 0.01639
  rank5 점수: 1/(60+6) = 0.01515

  1위 vs 6위 점수 비율: 0.01639 / 0.01515 = 1.08배 (매우 완만)
  → 양쪽 등장 효과가 지배적: 2/(60+6) = 0.03030 >> 1/(60+1) = 0.01639
```

k를 작게 했을 때의 위험:
```
k=5 환경에서 소규모(후보 6개):
  rank0 점수: 1/(5+1)  = 0.1667
  rank5 점수: 1/(5+6)  = 0.0909

  1위 vs 6위 점수 비율: 0.1667 / 0.0909 = 1.83배 (가파름)
  → Dense 1위가 Sparse 보완 효과를 압도할 가능성 있음
```

k=60은 Cormack et al.이 대규모 검색(수백~수천 문서)에서 도출한 값이지만, 소규모(수십 문서)에서도 "양쪽 등장이 단독 등장을 항상 이긴다"는 핵심 원칙을 수식으로 보장하므로 그대로 채택.
